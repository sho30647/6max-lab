# 判断審査（bot-judge）を呼ぶ

審査をするのは `bot-judge` エージェント（`.claude/agents/bot-judge.md`）。このスキルは、呼び出し側（会話の相手である私）が、依頼文をそろえて渡し、結果をオーナーに返して記録するまでの手順。

## 1. 何を審査するかを決める
- **1つの判断（ハンド）**：ボットの1手への違和感。
- **考え方・数字・測り方**：ボットの定義や数字の是非、変更の効果の読み方など、1ハンドではないもの。

## 2. 依頼文に入れるもの（bot-judge は会話を見ていない）
**1つの判断のとき**（足りなければ、オーナーに1問だけ聞くか、判断の記録・デモの履歴から集める）
- ゲーム（リング／MTT）、有効スタック、両者のポジション、各アクションのサイズ（bb）、スート付きのボード、ボットの手
- 相手の情報：人間かボットか、タイプ、スタッツ、観察メモ
- 判断トレースの全文（①〜⑧）。あれば必ず
- オーナーが感じた違和感（言葉のまま）

**考え方・数字・測り方のとき**
- オーナーの違和感・質問（言葉のまま）
- 関係するファイルと行、今の数字、これまでの経緯（`docs/decisions.md` の該当項）
- 手元の測定結果（数字・件数・誤差・使ったテスト）と、再現のしかた
- 返してほしいもの（理由の順位、確かめ方、案とメリット・デメリット、おすすめ、指示書の考え方の変更に当たるか）

どちらも「コードも指示書も直さない」と書く。

## 3. 呼び出す
`Agent` で `subagent_type: bot-judge`。長くかかりそうなら背景で回し、オーナーに「頼んだ」とだけ短く伝える。

## 4. 結果をオーナーに返す
- **1つの判断のとき**：`bot-judge.md` の「返答の形」の7項目（bot-judgeの判断と根拠／ボットの判断の評価と根拠／原因／何をどう直すか／条件／今回のハンドのアクションの変化／損の見込み）を、**そのままの順で**伝える（オーナーが bot-judge の正しさを確かめるため。CLAUDE.md）。
- **考え方・数字のとき**：結論を1〜2行で先に。案があれば、メリット・デメリットを表で。
- 指示書（`docs/postflop_spec.md`）の考え方の変更に当たる案は、**オーナーに1問で聞く**（冒頭に「あなたに答えてほしいのは○○」、選択肢つき）。答えが出るまで直さない。
- 指示書の範囲内の数字の調整なら、聞かずに `bot-strength` に渡してよい（CLAUDE.md の運用ルール）。

## 5. 記録する
- bot-judge が返す「記録用の1行」を、`docs/hand_reviews.md` の表のいちばん上（見出しのすぐ下）に足す。対応が決まったら「対応」欄を書き足す。
- 記録だけのコミットは、作業中のブランチに入れる（`main` に直接 push しない）。

## やらないこと
- ボット（`bot/`、`index.html`）・`params.js`・指示書を、このスキルの中で直すこと。直すのは、オーナーが決めてから `bot-strength` に渡す。
