# 夜間の判断審査（新ボット）

毎晩、日本時間の **1:24・2:24・3:24・4:24（作業の回）と 5:24（作業＋朝のレポートの回）** に、新しいセッションとして起動される。**各回は前の回の記憶を持たない。** 記憶は次のファイルだけ（どれもブランチ `claude/night-review-log` にある）。

- `docs/night-review/queue.json`：審査の順番待ち（見つかった局面と、その見本のハンド）。**夜をまたいで残る。** 審査しきれなかったものは、次の回・次の夜に続きから審査する。
- `docs/night-review/<日付>.md`：その夜の作業記録（各回が追記し、5:24の回が朝のレポートとしてまとめる）。日付は、作業を始めた夜の日付（1時〜6時の回は前日の日付）。

**手動の回**（昼間などに `review-now` スキルが予約した回）も、この手順書のとおりに動く。違いは2つだけ：作業記録の名前は、起動の指示文にある名前（例：`2026-10-27-1400`）を使う。「5:24の回」と書いてあるところは「最後の回」と読みかえる（最後の回だけ通知つきでレポートを出す）。
- `docs/hand_reviews.md`：審査の記録。

**この作業はボットを直さない。** 直すかどうかはオーナーが朝のレポートを見て決める（オーナーの方針、2026-10-26）。

## やらないこと（必ず守る）
- `bot/`・`index.html`・`mtt/`・`docs/postflop_spec.md`（指示書）・`docs/decisions.md` の変更。ボットの数字（`params.js`）の変更。
- `main` や `staging` へのマージ、`main` 向けのPR。
- 指示書の考え方を変える案の採否を決めること（オーナーが決める。CLAUDE.md）。

## 0. 始める前に（毎回）
1. `TZ=Asia/Tokyo date` で時刻を確認する。**起動から50分以内に**、その回の作業を終えてコミットとpushまで済ませる（途中で止まっても、pushしたところまでは残る。次の回は続きから）。
2. 作業ブランチは `claude/night-review-log`。
   - origin にあれば checkout して pull し、`git merge origin/staging` で最新のボットを取り込む（衝突したら、記録のファイルは両方の行を残す）。
   - 無い、またはそのPRがマージ済みなら、`origin/staging` から作り直す（`git checkout -B claude/night-review-log origin/staging`）。マージ済みで作り直すときも、`queue.json` は前のブランチから引き継ぐ（`git show <前のブランチ>:docs/night-review/queue.json`）。
3. `docs/night-review/queue.json`（無ければ空：`{"items": []}`）と、`docs/hand_reviews.md` を全部読む。

## 1. その回にやることを決める
- **順番待ち（`status` が `pending`）が残っていれば、先に審査する（2へ）。** 探すのは、順番待ちが空になってからにする。
- 順番待ちが空で、残り時間が40分以上あれば、探す（1-Aへ）。
- 5:24の回は、残りの時間に関係なく、最後の15分を朝のレポート（5）に使う。

### 1-A. 探す（機械、30〜35分）
```
node tests/spec-scan.mjs --minutes=30 --top=10 --seed=<日付の数字と時の数字から決める。例：2026102702 → 2026102702> --out=/tmp/scan.json
```
- 新ボット同士で打ち、ボットの判断を1つずつ「別の手（降りる↔コール、チェック↔ポットの2/3のベット）」でやり直して、結果の差を測る。似た局面をまとめた「グループ」ごとに、差の平均が、ばらつきを考えても0より大きい（99%）ものを、損の大きい順に最大10個出す。各グループに、平均に近い見本のハンドが2つ付く（相手の手札は入れていない）。シードを回ごとに変えるので、毎回ちがうハンドで測る。
- `FAIL` を出したり、途中で止まったりしたら、何が起きたかを作業記録に書いて 3 へ進む。
- 出たグループを、順番待ちに足す（`queue.json` の `items` に、`{key, n, mean, per100, E, need, spr, hands, foundAt, status: "pending"}`）。ただし、
  - 順番待ちや `hand_reviews.md` に同じグループ名（`key`）があれば、新しく足さず、その項目の `seen`（見つかった回数）を1増やし、`n`・`mean`・`per100` を今回の値も記録しておく（`history` に足す）。何度も出ること自体が、優先度の材料になる。
- 順番待ちは、`per100`（100フロップあたりの損）の大きい順に並べ直す。

**読み方の注意**：相手はボット自身なので、「別の手が得だった」のは、ボットの穴のせいとは限らない。相手側（同じボット）の応じ方の穴（例：ベットに降りすぎる）のせいのこともある。どちらなのかは、bot-judge が理論で決める。

## 2. 審査（bot-judge）
順番待ちの先頭から、**その回で最大3つ**（残り時間が足りなければ減らす）。グループ同士は独立なので、並行で呼んでよい。
1. `hand_reviews.md` に、同じ局面（ストリート・場面・アクション）で同じ根本原因の行があり、「オーナーの判断待ち」か「対応中」なら、審査し直さない。その項目は `status: "known"` にし、作業記録に「既出（#番号）。見つかった回数・損の大きさ」とだけ書く。
2. 新しいものは、`bot-judge` エージェントに渡す。依頼文には、次を全部書く（bot-judge は会話を見ていない）。
   - 見本のハンド1つ目のハンドヒストリー：ライン、ポジション、有効スタック、プリフロップ、それまでのアクション（bb）、スート付きのボード、ボットの手札、ボットのアクション。`hands[0]` の項目をそのまま、読みやすく並べる。
   - 判断トレースの全文（同じ項目の `trace`）。
   - 相手の情報：「相手は同じ新ボット（`bot/spec/`）。実際のレンジは `bot/spec/` から分かる」。
   - 機械が見つけた理由：グループ名、件数、別の手との差の平均（bb）、100フロップあたりの損、見つかった回数、注意（相手が自分なので、相手側の穴の可能性もある）。2つ目の見本のハンドも、参考として付ける。
   - 頼むこと：「`bot-judge.md` の返答の形（7項目）で。ボットが理論上正しいなら、そう言い切り、別の手が得になった理由が相手側（同じボット）の応じ方の穴かを見て、そうならその穴を、原因と直し方の形で書いて。指示書の考え方の変更に当たる案は、採否を決めずに『オーナーの判断事項』として、メリット・デメリットとおすすめを書いて。」
3. bot-judge が STEP0 で質問を返したら（情報が足りない）、見本の2つ目で頼み直す。それでも止まったら、その質問を作業記録に書き、`status: "question"` にする。
4. 審査が終わったら `status: "reviewed"` にし、`review`（hand_reviews の番号）を付ける。

## 3. 記録と保存（毎回、終わる前に必ず）
- 作業記録 `docs/night-review/<日付>.md` に、その回の分を追記する：時刻、探した量（ハンド数・判断数・時間）、順番待ちに足したもの、審査したもの（bot-judge の7項目をそのまま）、既出のもの、残りの順番待ちの件数。
- `docs/hand_reviews.md` の表に、新しく審査したものを1行ずつ足す（新しいものを上に）。局面の頭に「夜間」、対応は「オーナーの判断待ち（夜間 <日付>）」。ボットが正しいと判定したものも「適切」として残す（同じ局面を審査し直さないため）。下に詳細の節（`## #番号 …`）を足す。番号は既存の続き。
- `git add docs/night-review docs/hand_reviews.md` → コミット（`夜間審査 <日付> <時>時：審査<件数>件、順番待ち<件数>件`）→ `git push -u origin claude/night-review-log`。
- 予約で動くセッションには GitHub のPR作成の道具が無いことがある。あれば、`staging` 向けの開いたPRが無いときだけ作る（題：「夜間の判断審査の記録」、変更は記録だけ）。無ければ作らない。マージはしない。

## 4. 回の最後の返答（1:24〜4:24の回）
通知は出ない。2〜3行で、その回にしたこと（探した／審査した件数、残りの順番待ち）だけ書く。

## 5. 朝のレポート（5:24の回の最後の返答）
オーナーが朝にスマホで読む（この回だけ通知が届く）。CLAUDE.md の「オーナーへの返答・質問の書き方」に従う。その夜の作業記録をもとに書き、作業記録の先頭にも同じものを置く。
- 1行目：結論（例：「今夜は損をしている局面を2つ審査し、1つは直す価値が高い。順番待ちは残り4つ」）。
- 審査したものごとに3行まで：どんな局面か（ふつうの言葉で）、bot-judge の判定（ボットが不適切／適切、損の大きさ）、直すとしたら何を変えるか（指示書の範囲内か、考え方の変更か）。
- 順番待ちの残りの件数（次の夜に続きから審査する）。
- 詳しくはブランチ `claude/night-review-log` の `docs/night-review/<日付>.md` にあると書く。
- 最後に質問を1つだけ：冒頭に「答えてほしいのは：」。例：「直すものを番号で選んで（なし、も可）」。考え方の変更に当たるものがあれば、その採否を、メリット・デメリットを並べて選択肢で聞く（そのときは、この1問だけにする）。
