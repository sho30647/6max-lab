# いまのボットの判断順序（リング・ポストフロップ）

対象：`index.html` の `botPostflopV3`（約2144行〜）。プリフロップは最後に短く。
MTT（`MT.on`）の部分は含めない。数字はコードの値。

## 0. 判断の前に作る材料（毎回、最初に計算する）

| 材料 | 中身 | 何を表すか |
|---|---|---|
| `e`（勝率） | 相手の想定レンジ（`p.rw` など）に対するモンテカルロ勝率。相手が3人以上なら170回、それ以下は250回 | 「いまの強さ」 |
| `q`（順位） | 自分の手が、**自分のレンジの中で**下から何%か（0〜1） | 「レンジの中での位置」 |
| `dr`（ドロー） | フラッシュドロー（4枚そろい・自分のホールカードを1枚以上含む）か、ストレートドロー（4連続）か。**はい／いいえの2値**。リバーは常にいいえ | 「未来の強さ」の全部 |
| `role` | フロップならプリフロップのレイズ側、ターン・リバーなら前のストリートでベットした側 | ベッターかコーラーか |
| `ip` | ポジション有利か | IPかOOPか |
| `n` | 残りの相手の人数 | 1人か複数か |
| `wet` | ボードの形（`texture`）。**濡れている／乾いている**の2値 | ボード |

使っていないもの：SRP／3bet／4betのポット種別（ポストフロップの頻度には入っていない。`S.raiseCount===0` が、ベット側でないIPの場面にだけ出てくる）、バックドア、ブロッカー、ペア＋ドローの組み合わせ、スタックの深さ（リング）。

## 1. 先に打つ場面（`toCall===0`）：頻度を先に決め、ハンドを当てはめる

```
① 頻度 F を決める（ハンドは見ない）
     ベット側    ：フロップ  相手1人 → IP(乾0.72/濡0.45)  OOP(乾0.50/濡0.33)、複数 → 0.30
                  ターン    相手1人 0.50 / 複数 0.30
                  リバー    相手1人 0.45 / 複数 0.25
     ベット側でない・IP・プリフロップのレイズが1回だけ（S.raiseCount===0）
                  → フロップ0.42 / ターン0.38 / リバー0.32（複数なら×0.5）
     それ以外（ベット側でない・OOPなど） → 0.06
   そのあと  F ×= ボットの性格(aggr)、0〜0.85に収める
   （調整用ノブ：ボードがA/K高なら cbetHi、9以下なら cbetLo などを掛けるが、通常のボットでは 1）

② F を3つに分ける（固定の比率）
     価値ベット枠 valueFrac = F × 0.62
        └ ナッツ級 nutFrac = valueFrac × 0.4   （大きいサイズ）
        └ 薄い価値 thinFrac = 残り60%          （小さいサイズ）
     残りの F×0.38 はブラフ枠（ブラフ量はサイズごとに bluffShare で逆算）

③ サイズの候補（ストリートごとに固定の確率で抽選）
     大(big)：フロップ 0.75/1.0、ターン 0.75/1.0/1.5、リバー 1.0/1.5/2.0 倍ポット
     小(small)：フロップ（濡れ 0.5/0.75、乾き 0.33/0.5）、ターン 0.5/0.75、リバー 0.33/0.5
     中(mid)：セミブラフ用

④ ハンドを上から当てはめる（上から順に判定。最初に当たったものを実行）
     a. 価値ベット：q が上位 (nutFrac+thinV) に入り、かつ e が基準以上（1人なら0.5、複数なら0.4）
                  ※ e>0.8 なら無条件で入る
         - q>0.93 でフロップ・ターンなら18%はチェック（トラップ）
         - ナッツ級（q が上位 nutFrac かつ e>0.7、または e>0.88）→ 大
         - それ以外 → 小
     b. ドロー（dr、フロップ・ターンのみ）
         確率 min(1, 0.6×(ブラフ量の合計)/0.2) でベット。e≥0.45 なら大、未満なら中
     c. 空振り（q<0.35 かつ e<0.4）
         ブラフ予算に応じた確率でベット。大と小の比率は、必要なブラフ量の比
     d. どれにも当たらなければ チェック
```

ポイント：①で決まる F は**全ハンド共通の枠**。②〜④は「その枠の中でどの手がどのサイズを使うか」を決めているだけで、**ハンドごとのベット確率そのもの**は決めていない（ハンドごとの確率は、上位から詰めた結果の0か1に近い値になる）。マージナルな手を中間の確率で打つ、ナッツ級を90%だけ打つ、といった形は作れない（トラップの18%だけが例外）。

## 2. ベットを受けた場面（`toCall>0`）：価格と勝率で決める

先に打つ場面とは別の仕組み。順番は次の通り。

```
① レイズ（リレイズを除く）
     q が上位12%(フロップ)/10%(ターン)/8%(リバー) かつ e>0.6 → 75%の確率でレイズ
       サイズ：フロップ 0.75/1.0、ターン・リバー 1.0/1.5 倍
② リレイズを受けた場面（raiseCount≥2）
     q>0.95 かつ e>0.7 → オールイン
③ 相手1人のとき
     ドロー（フロップ・ターン）→ drawRaise の確率でレイズ（フロップ0.28、ターン0.12）
     リバーで q<0.12 → 5%でブラフレイズ
④ 調整用の分岐（通常のボットでは使わない）：ターン・リバーのコール基準など
⑤ コールかフォールドか
     potOdds = コール額／(ポット+コール額)、alpha = コール額／ポット
     foldCut = alpha の 1/n 乗（相手が増えるほどフォールドしにくい）
     - byOdds：勝率 e（+ドローの手なら0.06のインプライド）≧ potOdds → コール
     - byMDF ：q が foldCut 以上（レンジの下位 foldCut をフォールドにする）、かつ 勝率が potOdds×0.55 以上 → コール
     - どちらも満たさない → フォールド
```

## 3. プリフロップ（`botPreflopRing`）

ポジションと状況（オープン／3bet／4betなど）ごとの**チャート**（`CH.*`）で、169のハンドクラスごとに「レイズ・コール・オールイン」の確率が決まっている。サイズは `preSize` で固定の倍率。ここは**ハンドごとの確率で決める形**になっていて、ポストフロップとは考え方が違う。

## 4. このメモの結論

| 項目 | 今の作り |
|---|---|
| 決める順番（先に打つ場面） | 場面で全体の頻度 F → F を分割（価値62%・ナッツ級は価値の40%） → ハンドを順位で上から当てはめる |
| ハンドの区別 | 勝率 `e`、レンジ内の順位 `q`、ドローの有無 `dr` の3つ |
| 未来の強さ | `dr` が真か偽か、の2値のみ |
| ボードの区別 | 濡れている／乾いている の2値（A/K高・9以下はノブ経由のみ） |
| ポット種別 | ポストフロップの頻度には入っていない |
| ハンドごとの確率 | 持っていない（上位から詰めるので、ほぼ0か1） |
| プリフロップ | ハンドごとの確率で決める（チャート方式）。ポストフロップだけ別の作り |
