### 初回の偵察（チャンピオン v6、シード1、各役 8,000ハンド、bb/100、正＝役の勝ち＝穴）
| 役 | 結果 | 読み取れること |
|---|---|---|
| riverBluff4 | **+3.1 ± 1.6（穴）** | v6はリバーの大きいベットに降りすぎ。`BACKLOG.md` 5と一致 |
| overbetBluff | +1.6 ± 2.8 | 同じ方向だが誤差の範囲内 |
| thinValue | +2.2 ± 4.6 | 誤差が大きく判断できない |
| bigFlopValue | +3.6 ± 6.2 | 平均は最大だが誤差が大きい。穴とは言えない |
| maniac | +2.1 ± 2.1 | 境界線上。フロップ・ターンで降りすぎの疑い |
| valueOnly | +0.4 ± 4.7 | 差なし |

| nit | 0.0 ± 2.2 | 差なし |
| drawTight | −1.8 ± 3.4 | 差なし。オーナーの観察5（ドローの払いすぎ）は、v6では数字に出ない（v6はターンのコール基準を上げてあるため、の可能性） |
| thinFold | −0.5 ± 2.1 | 差なし。観察3（弱いペアの払いすぎ）も数字に出ない |

- 判定の見直し：最初は「平均の最大値」を物差しにしていたが、誤差の大きい役（bigFlopValue ±6.2）が選ばれてしまうため、「誤差を超えて勝つ役＝穴」を数える形に変えた（`tests/ring-league.mjs` の eval / confirm は `--target` で論点の役を指定）。
- ずれの大きい役ほど誤差が大きい（±1.6〜±6.2）。thinValue・bigFlopValue・valueOnly は、8,000ハンドでは穴かどうか判定できない。
- 最初の論点：riverBluff4（リバーの大ベットへの降りすぎ）。`BACKLOG.md` 5で、コール基準を手で下げる案（riverDefend）は誤差を超えて縮められなかった。根本は「相手のベットサイズで相手レンジを読み替えない」こと（`BACKLOG.md` 1）なので、そこから挑戦者を作る。
