# エージェント化の考え方（2026-10-19の議論のまとめ）

オーナーの狙い：ルーティンの仕事を、オーナーの方針を理解したAIエージェントに自動で任せる。

## エージェントの中身
モデルは毎回まっさらで起動する。会話は持ち越せない。エージェントの正体は、次の部品のセット。
| 部品 | 夜間ボット研究での実体 |
|---|---|
| モデル（頭脳） | 毎晩起動するClaude |
| 道具（手足） | シェル、ファイル編集、ベンチのスクリプト、git |
| 指示（方針と手順） | `policy.md`（方針）、`SKILL.md`（手順） |
| 記憶（記録） | `journal.md`、`league.json`、`results.jsonl` |
| 起動の仕組み | 予約（毎晩2:02〜5:02、日本時間） |

「方針を理解している」状態は、方針をファイルに言語化して、毎回読ませることで作る。変えるときは予約ではなくファイルを直す。

## 予約とレシピの関係
- 予約（Anthropicのサーバー）に保存されるのは、時刻と短い指示文だけ。
- 中身のレシピはリポジトリ内。起動したセッションが全部読み、1つのセッションが作業全体をやる。「どれか1つが動く」のではない。
- 再現性：測定と判定はスクリプトなので同じ数字が出る。「穴の原因は何か」「どう直すか」の考えはぶれる。

## エージェント定義にする案（バックログ6）
- `.claude/agents/bot-lab.md` に、役割・手順・使う道具・モデルと考える深さを書く。予約の指示は「bot-labを起動して」。
- 得られるもの：道具とモデルの固定、役割ごとの名前と整理。記憶は増えない。
- 今は移さない理由：①段が増えて失敗の場所が増える ②予約から直接エージェントを指定できるか未検証 ③役割がまだ1つしかない。
- 移す時期：数晩回して安定してから。役割が増える段階で価値が出る。

## 任せる範囲の設計
手順が決まっていて、結果を数字で判定できる仕事から任せる。方針そのものを変える判断は、オーナーがやる。エージェントを自由にするほど、ぶれて予想外のことをするため。
