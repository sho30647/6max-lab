# ボット研究所の方針書

夜間の自動ループ（`.claude/skills/bot-lab`）は、この方針書に従ってボットを強くする。方針を変えるのはオーナーだけで、エージェントはこのファイルを書き換えない（気づいたことは実験ノートとレポートに書く）。

## 1. 目的
**最優先：8章の「相手のベットへの応答の理論」（オーナー指定）に沿うこと。** 理論と数字が食い違ったら、数字を優先せず、レポートで質問する。

**崩れにくく正しい相手**を作る。目指すのはGTOの均衡。
- 「旧版に勝つ」ことは目的ではない。**どんな打ち方で突かれても、損が小さい**ことが目的。
- 物差しは「穴」＝リーグ（`league.json` のエクスプロイト役）の中で、本体に**95%の誤差を超えて**勝つ役。穴を1つずつ塞ぎ、0にする。
  - 平均の勝ち額が一番大きい役を物差しにしない。誤差の大きい役ほど、偶然大きく出やすいため。
- 全レンジの均衡計算はしない。ロジックで説明できる穴を見つけて、塞ぐ。

## 2. 範囲
- 対象：**リングゲーム（6人、100bb）のポストフロップ**。`index.html` の `botPostflopV3` と `BOT_TWEAKS` / `RING_VER`。
- 対象外：プリフロップ、MTT（`MT.on` のとき `X={}` で、つまみは効かない。この形を壊さない）、画面、`firestore.rules`。
- `botPostflopV2` と、過去の版（`BOT_TWEAKS` の番号）は比較用に残す。消さない。

## 3. 守ること
1. **公開情報だけで判断する。** ショーダウン前に相手の手札（`S.players[i].hole`、自分以外）を判断に使わない。相手のレンジ（`rw`）、ボード、ベットの流れ、ポジションは使ってよい。
2. **1ラウンド1論点。** 2か所を同時に直さない。
3. **練習相手として不自然にしない。** 次のどれかに当たる版は、強くても採用しない。
   - ベットを受けたときのフォールド率が、理論の最低防御（1−α、αはベットがポットに占める割合）から20ポイント以上ずれる（`node tests/ring-bench.mjs stats <版>` で確認）。
   - あるストリートで「常に〇〇する」（ブラフ0%、コール100%など）になる。
   - つまみの倍率が、既定値の 0.3倍〜3倍 を超える。
4. 新しいつまみを足すときは、**つまみを指定しない版の挙動が1ハンドも変わらない**こと（`node tests/ring-regression.mjs` が OK のまま）。

## 4. 採用の基準
挑戦者（直した版）は、次をすべて満たしたときだけ新チャンピオンにする。
1. `node tests/ring-league.mjs eval <挑戦者> --target=<論点の役>` が **PASS**。中身は3つ：①チャンピオンとの直接対決で、誤差を超えて負けていない ②論点の役の勝ち額が、誤差を超えて下がった ③他の役で新しい穴が開いていない（挑戦者に誤差を超えて勝ち、かつチャンピオンのときより誤差を超えて大きい役がない）。
2. 別のシード（101）での確認 `node tests/ring-league.mjs confirm <挑戦者> --target=<論点の役>` も **PASS**。シードに過剰適合した変更を弾くため。
3. 3の「不自然さ」に当たらない。
4. 回帰テスト：`node tests/ring-regression.mjs`（チャンピオンを替えたら `--save` で更新し、理由を実験ノートに書く）、`node tests/engine-nseat.mjs`、`node tests/ring-bot-v6.mjs` ほか、`tests/ring-*.mjs` が通る。

満たさなければ、変更は捨てて、結果だけ実験ノートに残す（失敗も記録）。

## 5. オーナーが感じている弱点（2026-10-19）
着手順は偵察の数字で決めるが、この5つは最初に疑う場所。

| # | 観察 | コードで確認した原因 | 対応するエクスプロイト役 |
|---|---|---|---|
| 1 | リバーの大ベットがほぼバリューしかない | ブラフの予算が小さい。大きいサイズのブラフは1〜2割（理論は33〜40%） | riverBluff4, nit |
| 2 | ポット以上のサイズがなく怖さがない | ターン・リバーに1.5倍・2倍はあるが、ナッツ級とわずかなブラフにしか使わない。原因は1と同じ | overbetBluff |
| 3 | 発展性のないサードヒットでコールしすぎ | コールは「レンジ内の順位」だけで決まり、次のストリートで良くなるかを見ていない | thinValue, valueOnly, thinFold |
| 4 | ブラフキャッチせず役の強さだけで押し引き。流れもブロッカーも見ない | ブロッカーの概念がない。相手レンジの絞り込みでサイズを見ていない（`BACKLOG.md` 1） | riverBluff4, maniac |
| 5 | ドローをオッズを気にせずコール | 勝率が「2枚見られる前提」。コールで買えるのは1枚。さらに一律6%の上乗せ | bigFlopValue, drawTight |

## 6. 理論値（補助の物差し）
- リバーでベットに含めるブラフの割合 ＝ サイズ÷(1＋2×サイズ)：33%→20%、50%→25%、75%→30%、100%→33%、150%→38%、200%→40%。
- ベットを受けた側の最低防御 ＝ 1−α：33%ベット→75%、50%→67%、75%→57%、100%→50%、200%→33%。
- ドローのコール：1枚で引ける確率がポットオッズを上回るか（＋現実的なインプライド）。フラッシュドローは1枚で約19.6%、両面ストレートドローは約17.4%。

## 8. 相手のベットへの応答の理論（オーナー指定・最優先）
2026-10-19にオーナーが指定。相手のベットに対するコール／フォールドは、次の3ステップで決める。

1. **相手のベットサイズから、降りる頻度を決める。**
2. **自分のレンジを、強さの順に並べ、弱いほうから順に降りるハンドを選ぶ**（降りる頻度に達するまで）。
3. **持っているハンドが、降りるハンドに入っているかを判定する。** 入っていれば降り、入っていなければコール（またはレイズ）。

### 8.1 降りる頻度（ベットサイズ別）
| 相手のベット（ポット比） | 降りる頻度 | 参考：理論上の最低防御で降りてよい割合（サイズ÷(1＋サイズ)） |
|---|---|---|
| 33% | 30% | 25% |
| 50% | 40% | 33% |
| 75% | 50% | 43% |
| 100% | 55% | 50% |
| 125% | 60% | 56% |

- 表は、最低防御より4〜7ポイント多く降りる設定（オーナー確認待ち：レポートの質問1）。
- 表に無いサイズ：表の間は線形補間。表の範囲外（33%未満、125%超）は「サイズ÷(1＋サイズ)＋5ポイント」。
- 相手が複数のとき（多人数ポット）は、この理論の対象外。今のロジックのままにする（質問で確認する）。

### 8.2 強さの見積もり（ステップ2の中身）
- 強さは、**今の役の強さではなく、このゲーム全体での強さ**（この先に良くなる可能性を含めた強さ）。自分がその場で持ちうるレンジ（`rw`）の全ハンドを、強い順に並べて決める。
- 将来性は大きく見積もる。フラッシュドロー、ストレートドロー、バックドアのフラッシュドロー、バックドアのストレートドロー、およびそれらの組み合わせ。
- 相手のブロッカーを考える。現時点でサードペアでも、発展性がなければ弱く見積もり、降りる側に入れる。
- 例（ボード A♥9♦6♥）：8♥7♥ は、J6 や K4 より、今は弱いが、フラッシュドローとストレートドローがあるので、ゲーム全体では強い。
- 例（同じボードで 8-5）：8♥5♥（フラッシュドロー＋ガットショット）と 8♦5♦（バックドアのフラッシュドロー＋ガットショット）は強く見積もる。8♠5♣（色が無く、ただのガットショット）は、降りる側でよい。

### 8.3 運用
- 今のボット（v6）は、強さを `strengthVal`（今の役の強さ）の順位で決め、リバーとターンでは勝率の閾値で降りている（`riverCall` `turnCall`）。8章の理論は、これと置き換わるもの。
- **進め方の目安（1ラウンド1論点）**：①ステップ1・3（サイズ別の降りる頻度の表）を、今の強さの順位のまま実装する ②強さの見積もりを「ゲーム全体での強さ」に置き換える（ドロー、バックドア） ③ブロッカーを入れる。順番はエージェントが決めてよい。
- **確認方法（適合度）**：`node tests/ring-bench.mjs stats <版>` を、サイズ別に細かくして、実際の降りる頻度が表から±5ポイント以内かを見る。リーグ（エクスプロイト役）は、理論に沿った版でも残る穴を見つける道具で、理論から外すための根拠にはしない。
- 理論に沿うと、v6が負けているエクスプロイト役（riverBluff4：リバーの大ベットへの降りすぎ。v6はポット超えのベットに約98%降りる）は、理論上すぐに縮む。
